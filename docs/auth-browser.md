# BKR-95 — регистрация, вход, кабинет и выход

**Границы:** первый работающий пользовательский путь на PostgreSQL. Исходная схема users/sessions — из BKR-94. Реализация не покрывает Яндекс OAuth, восстановление пароля, все старые разрешения на книги и пользовательские настройки.

## HTTP

- `GET /register` и `GET /login`: настоящие HTML-формы с одноразово выданным браузеру непредсказуемым CSRF-токеном. Кеширование запрещено.
- `POST /register`: проверка имени, почты, пароля (12–128 символов), Argon2id выполняется вне потока обработки HTTP. **Создание пользователя и первого сеанса атомарны** в PostgreSQL. Дубликат защищён уникальным индексом.
- `POST /login`: общая ошибка для неизвестного пользователя и неверного пароля; для неизвестного пользователя всё равно выполняется Argon2id. При удаче создаётся **новый** случайный сеанс, сохраняется только SHA-256 токена.
- `GET /me`: для гостя и отозванного/истёкшего сеанса перенаправление на вход; для владельца — HTML с экранированным именем. Ответ не кешируется.
- `POST /logout`: требует CSRF и отзывает сеанс. Повторный запрос после отзыва не раскрывает данные; cookie удаляется.

## Безопасность

- В рабочем режиме имена cookie начинаются с `__Host-`, включены `Secure`, `HttpOnly`, `SameSite=Strict`, `Path=/`, не задан `Domain`. Срок сеанса 7 дней, CSRF — 1 час. Токен нигде не пишется в логи.
- Для отправки форм обязательно совпадение случайного CSRF-токена в скрытом поле и cookie. Cookie не доступна JavaScript. Запрос с посторонним `Origin` или `Sec-Fetch-Site: cross-site` отвергается даже при правильном CSRF.
- Сайт **не принимает** параметр `next` или произвольные внешние адреса для перехода после входа: успешный переход строго на `/me`.
- Ограничение попыток — атомарные счётчики PostgreSQL на нормализованный email (до 8 за 10 минут) и IP сетевого соединения (до 60 за 10 минут). Заголовкам `X-Forwarded-For` пользователь доверять не может. Для работы за обратным прокси все запросы могут приходить с IP самого прокси; для производственного размещения нужен отдельный сетевой лимит на границе и доверенное определение IP.
- Длина тела форм — не более 4096 байт. Данные проверки/CSRF/сеанса не кешируются. Ошибки БД возвращают отказ без её внутреннего текста.

## Запуск

Нужно задать `DATABASE_URL` для PostgreSQL 18. Сервер применяет новую версионированную миграцию `202610120003_auth_attempts.sql` после пользователей и книг. Применённые миграции **не переписывать**.

**Для доступа через HTTPS:** задайте `BOKARUST_PUBLIC_ORIGIN=https://your.domain` (точный внешний протокол, домен и, если нужно, порт), обеспечьте HTTPS на обратном прокси, используйте Secure-cookie. Порт 5432 не публиковать. Запросы с неправильным Origin будут отвергнуты.

**Локально только на loopback через HTTP** можно дополнительно задать `BOKARUST_INSECURE_COOKIES=1`. Эта настройка запрещена при привязке сервера к общедоступному сетевому адресу. Для демонстрации в памяти формы остаются отключёнными: вход без PostgreSQL не предлагается.

## Проверки

- `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`
- Обычные Rust-тесты проверяют валидацию, формат защищённых cookie, CSRF и посторонние Origin.
- `TEST_DATABASE_URL=postgres://.../bokarust_ci cargo test -p bokarust-web --test integration_auth_flow -- --ignored`
- Сквозной тест на одноразовой PostgreSQL: регистрация → кабинет → обновление → выход → повторный вход, запрет гостя, CSRF, посторонний Origin, открытое перенаправление, экранирование HTML и атомарный ограничитель запросов. Тест без `TEST_DATABASE_URL` падает при явном запуске и не может использовать БД вне списка безопасных тестовых имён.
- В GitHub интеграционный тест обязателен внутри задания `rust` и повторяется в ночном полном наборе.

## Дополнительная защита от истощения ресурсов

- В дополнение к атомарным счётчикам попыток PostgreSQL каждый экземпляр Axum допускает не более **4 одновременных операций Argon2id**, общих для регистрации и входа.
- При занятии всех четырёх мест следующий запрос отклоняется с HTTP 429 **до запуска вычисления пароля**; очередь дорогостоящих вычислений не разрастается. Место возвращается после завершения операции, включая ошибку.
- Ответы страниц авторизации снабжены CSP без исполнения скриптов и со строгим `form-action 'self'`, `frame-ancestors 'none'`, а также `X-Frame-Options: DENY`. Таблица стилей разрешена только со своего узла.
- Unit-тест воспроизводит занятость единственного места и проверяет 429, освобождение и повторную работу; тест HTTP проверяет ограничения заголовков.
- Механизм по-прежнему не заменяет сетевую защиту и ограничения на краю системы.

## Что остаётся до публичного запуска

Наличие тестов не равно независимой проверке безопасности.
