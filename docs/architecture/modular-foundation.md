# Букраст: первый модульный каркас

**Статус:** рабочая основа для обсуждения и расширения. Никаких публичных данных, пользователей или платежей этот PR не обслуживает.

## Зависимости и сборка

```text
       ┌───────────────┐
       │ web (Axum)    │        HTTP/API и позже SSR UI
       └──────┬────────┘
              │
    ┌─────────▼────────┐     ┌───────────────┐
    │ application      │◄────│ adapters      │ PostgreSQL / S3 / jobs
    └─────────┬────────┘     └───────────────┘
              │                     │
       ┌──────▼─────────────────────▼┐
       │ domain: независимые правила │
       └─────────────────────────────┘
```

Физическая зависимость Cargo: `domain` (без внутренних зависимостей) → `application` → `adapters`; `web` связывает их и не принимает доменных решений. `application` определяет **узкие интерфейсы**, реализуемые `adapters`. Обратные связи и циклы запрещены. Редакторское `editor-core` из отдельного PR временно автономно.

## Не плодим пакеты

- `domain` содержит `books`, позже `chapters`, `publishing`, `access`, `commerce` и `identity`. Из одного файла на предметную возможность начинаем, разделяем по обязанностям при росте.
- `application` содержит узкие команды и запросы каждого домена, здесь интерфейсы чтения/записи и транзакционные границы.
- `adapters` содержит реализации `application`-интерфейсов: сейчас только память для демонстрации; PostgreSQL и S3 подключаем по отдельным задачам.
- `web` — один реальный сервер, обработчики и будущие SSR/Leptos-компоненты. Сессии и права никогда не доверяются HTML.
- `worker` — **не создавать пустым заранее**. Позже он будет вторым процессом композиции на тех же приложениях и адаптерах, когда появится долговечная очередь.

**Не создавать** общий `utils` / `common` с перемешанной логикой, `service.rs` на тысячи строк, тип `AppContext` со всеми зависимостями или универсальные репозитории на все таблицы.

## Первый работающий сквозной путь

`GET /api/v1/books` → `application::catalog::ListPublicBooks` → `PublicBookRepository` → `adapters::in_memory::InMemoryCatalog` → `domain::books::Book`.

Установлен лимит 1–100 книг за запрос; попытка выдать закрытую книгу из ошибочного адаптера обрабатывается как отказ. `/healthz` проверяет только локальный запуск, **не готовность PostgreSQL**. Память — временная подмена. До создания базы каталог по умолчанию пуст.

## Изоляция и договорённости

1. Любой доменный путь имеет **одного владельца** записи и явную границу транзакции. Разные домены общаются через операции уровня `application`, а не через таблицы чужого домена.
2. `domain` не импортирует Axum, Tokio, SQLx, S3, HTTP или клиентские компоненты. Типы книги не должны раскрывать SQL-структуры.
3. У каждой новой операции минимум: контракт входа/выхода, проверка прав, неуспешный сценарий и быстрый тест. Для денег и публикации — тест повторного вызова и неопределённого результата до их подключения.
4. Доменные тесты запускаются независимо от HTTP и БД; настоящие интеграционные тесты с PostgreSQL находятся в отдельной группе.
5. Лимиты из `architecture/policy.toml`: предупреждение после 400 строк, запрет после 600 (в тестах 800/1000), контроль прямых потребителей и запрет циклов; CI должен обрывать зависшие проверки.
6. Любая недоказанная совместимость со старым Python отмечается как исследование, не как готовность; `booka` — только референс.
