# PostgreSQL: первый долговечный каталог

**Границы:** техническая задача [BKR-80 в Notion](https://app.notion.com/p/3f632a84beec812e9cf2c1a0c18ecb1e). Реализованы схема книг, чтение публичного каталога из PostgreSQL и проверка договора на настоящей БД. Это не авторизация, не публикация и не перенос исторических данных Booka.

## Источник истины и инварианты

- Каждое произведение определяется парой `(source_identity, target_language)`, не ссылкой, slug или командой. Столбцы нормализованы: пробелы запрещены по краям, язык в нижнем регистре ASCII.
- PostgreSQL отвергает повторы в этой паре уникальным ограничением, включая одновременные вставки.
- Читательский запрос фильтрует `visibility='public'` в SQL; `application` также отвергает любые черновики, случайно возвращённые адаптером.
- Отдельный частичный индекс `books_public_id_idx` поддерживает ограниченный, устойчиво отсортированный список по `id`. Лимит от 1 до 100 применяется до SQL и параметризован в запросе.
- БД и доменная модель ограничивают длину заголовка 200 символами; PostgreSQL выдаёт `bigint`, который адаптер проверяет перед преобразованием в `u64`.
- SQL-ошибки, неожиданные данные и закрытый пул превращаются в отказ публичного запроса 503 без раскрытия подробностей.

## Запуск

1. Установить PostgreSQL, создать отдельную БД и роль приложения. Не открывать порт 5432 в интернет.
2. Установить `DATABASE_URL=postgres://USER:PASSWORD@127.0.0.1:5432/DATABASE` через окружение/секреты.
3. Запустить `cargo run -p bokarust-web`. Миграции встроены в бинарный файл, выполняются перед началом приёма запросов. Роль должна иметь права на DDL в первой версии; позже отделить роль применения миграций.
4. Для демонстрации без БД можно указать только `BOKARUST_DEMO_IN_MEMORY=1` и адрес обратной петли. Демонстрационный режим нельзя публиковать в интернете.

Миграции односторонние: применяются из единого каталога `crates/adapters/migrations/` через общий `MIGRATOR` из `bokarust-adapters`. Сначала применяется миграция учётных записей `202610120001_create_accounts.sql`, затем книг `202610120002_create_books.sql`. Веб-сервер и `migrate_accounts` используют один и тот же набор версий. Изменения уже применённой миграции запрещены; для эволюции создавайте новую. `build.rs` следит за изменением SQL-файлов.

## Проверки

- `.github/workflows/postgres-catalog.yml` поднимает PostgreSQL 18 и запускает Rust-тест `postgres_public_catalog`.
- Тест проверяет также совместимость с миграциями пользователей и сеансов (BKR-94): обе точки входа применяют общий набор версий повторно без ошибок.
- Проверяются повторное применение миграций, уникальность ключа, независимые переводы, нормализация языка, сокрытие черновиков в JSON и HTML, экранирование заголовка, предел запросов, гонка двух вставок и отказ 503 при закрытии пула.
- Локально: `TEST_DATABASE_URL=postgres://.../bokarust_test cargo test -p bokarust-web --test postgres_public_catalog`. **Тест очищает таблицу** и отказывается работать, если имя БД не равно `bokarust_test`.
- При обычном `cargo test --workspace` без `TEST_DATABASE_URL` интеграционный тест пропускает доступ к БД; за его выполнение отвечает отдельная обязательная проверка CI.

## Не входит

Веб-авторизация, создание/редактирование книг, права авторов, платные главы, карточки книг, пагинация, резервное копирование и проверка готовности БД. `/healthz` остаётся лишь проверкой живого процесса. Нельзя считать эту схему готовой к публичному запуску или объединять без зелёного CI.
