# Контроль архитектуры Букраста

Этот каталог содержит исполняемые правила и будущий реестр границ модулей.

## Быстрые проверки

```bash
python -m unittest discover -s tests/architecture -p 'test_*.py' -v
python tools/architecture_check.py --all
python tools/architecture_check.py --base origin/main --module-report .repo-check/rust-module-impact.json
```

Проверка не требует сетевых запросов и сторонних Python-библиотек. Она проверяет
количество строк, конечные сроки GitHub Actions, локальные связи Cargo-пакетов,
направление зависимостей, циклы и прямой охват пакетов.

**Область применимости:** по `Cargo.toml` проверяются зависимости между
пакетами, а `tools/rust_module_graph.py` строит граф модулей **внутри Rust-пакета**:
обрабатывает видимые `mod`, `use crate/self/super`, прямые `crate::...`
и групповые импорты. Считает прямых потребителей, циклы, нарушенные
границы доменов и обратный охват изменённых файлов. Отчёт сохраняется в
`.repo-check/rust-module-impact.json` и прикладывается к проверке PR.

**Важно:** это быстрый статический анализ, не компилятор Rust и не полная карта
покрытия тестами. Макросы, условная компиляция, `#[path]`, внешние пакеты
и часть нестандартных форм синтаксиса могут скрывать связи. Не использовать
его в одиночку, чтобы **пропускать** тесты. Изменения общего контракта и
неизвестные зависимости пока требуют широкого набора проверок.
До появления Cargo workspace проверки Rust-модулей неприменимы.

Порог для исходника: предупреждение после 400 строк, запрет после 600;
для теста — 800 и 1000. Обычному пакету или файлу-модулю разрешено до 8 прямых потребителей
без предупреждения; более 15 запрещено. Общие значения и идентификаторы
могут иметь узкое исключение через `shared_modules`. Общие
маленькие типы могут принадлежать слою `shared`.

Каждый пакет указывается в `architecture/policy.toml` как `shared`,
`domain`, `application`, `infrastructure` или `edge`. Исключения
разрешены только для `FILE_SIZE` и `FANOUT` с датой, причиной и задачей.
При совместном размещении нескольких доменов в одном пакете объявляйте
`module_owners` и разрешённые связи в `domain_dependencies`.
Для безопасности, циклов, отсутствующих проверок и нарушений слоёв исключений нет.

## Необходимые дополнительные этапы

- Расширить разбор `use`, `mod`, `pub use` полноценным синтаксическим
  деревом Rust, обработкой `#[path]`, макросов и условной компиляции.
- Построить карту фактического покрытия тестами и безопасный выбор тестов
  по затронутым пакетам/контрактам с резервным полным запуском.
- Подключить исполнение `cargo nextest run -P ci` в Rust-конвейере после
  появления рабочего Cargo workspace. Пока добавлена только
  `.config/nextest.toml`: 10 с на обычный тест, 60 с для
  `integration_`, 10 мин на запуск, остановка при первой ошибке без повторов.
  Длительный профиль `nightly` ограничен 30 минутами; документационные
  тесты надо выполнять отдельно командой `cargo test --doc`.
- Контроль владельцев данных при появлении постоянного хранилища.
- Браузерные проверки редактора после объединения его отдельного прототипа.

Существующий [прототип редактора](https://github.com/calex794/bokarust/pull/1)
остаётся отдельным незавершённым изменением. Эти проверки не утверждают,
что он успешно собирается или прошёл браузерные испытания.
