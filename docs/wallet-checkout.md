# BKR-31 · Списание за главу с внутреннего кошелька — первый срез

Основание: [P-09, P-10 и P-15 продуктовой конституции](https://app.notion.com/p/3cd32a84beec810b945bd914417a180f), [задача BKR-31](https://app.notion.com/p/3f632a84beec81e590f1cf71d377cf0d), [В4.01](https://app.notion.com/p/3f632a84beec81b08409c15ba1f8bf15).

## Реализовано

- Читатель видит платные опубликованные главы в карточке книги, без выдачи их текста. Закрытая форма `/chapters/{chapter_id}/buy` показывает исторический `version_id`, цену и остаток собственного кошелька; она защищена сеансом, CSRF, Origin, no-store, noindex, строгим CSP.
- **Цена и единицы в этом первом срезе:** целое `chapters.price_amount` — копейки RUB. Это ограничение реализации, которое надо отдельно сверить с финансовой моделью Booka до подключения настоящих пополнений и выплат. Покупка не переводит никакие средства на кошелёк автора и не обещает вывод.
- Публичный POST не принимает получателя, размер списания или редакцию на доверии. Цена/версия проверяются повторно в PostgreSQL под блокировками строки главы, книги и публикации. Изменение цены/версии до подтверждения даёт 409 без записи денег или права.
- `reader_wallet_accounts` хранит доступные для покупок копейки. `reader_wallet_entries` — неизменяемый журнал списаний и отдельно заранее проверенных пополнений. `chapter_purchase_commands` хранит успешный ключ действия для разборов сетевых повторов и неизвестного результата.
- **Одна транзакция PostgreSQL**: блокировка строки кошелька → запрет второй покупки уже закреплённой главы → списание только при достаточном остатке → неизменяемый `chapter_purchase_facts` → существующий триггер записи `library_purchased_chapters` → журнал списания → фиксация результата ключа. Любая ошибка откатывает всё.
- Повтор с тем же ключом и той же ценой/версией возвращает подтверждённое приобретение без повторного списания, даже если нынешняя редакция/цена позже изменилась. Повтор с другим payload и тем же ключом отвергается; новый ключ для уже купленной главы тоже не списывает повторно.
- При двух параллельных покупках разных глав одного пользователя деньги сериализуются одной блокировкой кошелька: потратить сверх остатка нельзя. После оплаты читатель попадает в уже защищённую читалку закреплённой версии `/me/purchases/{chapter_id}`.

## Пока сознательно не включено

- Пополнение кошелька извне, платёжный провайдер и проверка подлинности его уведомлений. Кредит из браузера отсутствует. В сквозных тестах средства заранее создаёт доверенный тестовый код в изолированной PostgreSQL; это **не доказательство настоящего эквайринга**.
- Полная двойная бухгалтерия платформы и автора, распределение комиссии, maturity/holds, вывод и возврат денег. Здесь есть только журнал **покупателя**: он не должен служить основанием ранней выплаты автору. Отзыв права от ранее добавленного PR #19 не является проведённым возвратом денег.
- Уточнение бизнес-правил: покупка скрытой книги и `pending_deletion` (нынешняя упрощённая модель не различает их), возрастные уровни, право автора покупать свой текст, удаление отдельной главы, точное отображение жёсткого блока. Текущий интерфейс продаёт лишь публичную выпущенную платную главу без административных ограничений. Это сознательно более узкая граница, **не утверждение нового постоянного правила**.

## Критерии выпуска

- Изолированная PostgreSQL, реальный HTTP: публичный текст платной главы недоступен, кнопка в карточке есть, посторонний не получает купленную версию, CSRF/Origin/сессия обязательны.
- Недостаточный баланс, старая цена, старый version_id, иной payload с прежним ключом, новый ключ для уже купленной главы не изменяют деньги и права.
- При успешном списании сходятся баланс, сумма неизменяемых записей журнала, версия факта сделки и версия в личной библиотеке.
- Параллельные покупки под одним кошельком не создают перерасход; ошибка вставки журнала после списания полностью откатывает версию, команду и баланс.
- Проверки: Rust fmt, check, Clippy, unit, реальные PostgreSQL интеграции, архитектура и следование сценариям Notion.

**Состояние В4.01 после этого среза остаётся «Частично», пока нет настоящего пополнения и полного денежного контура.**
