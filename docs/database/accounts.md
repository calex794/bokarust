# PostgreSQL: учётные записи и сеансы (BKR-94)

**Статус:** создана схема БД и инфраструктурные операции. Это ещё **не работающий вход на сайт**: маршруты регистрации, входа, кабинета и выхода будут реализованы и проверены отдельно в BKR-95.

## Реализовано

- users: нормализованная почта (уникальность гарантирует PostgreSQL), отображаемое имя, **только Argon2id-хеш** пароля, время создания.
- sessions: идентификатор пользователя, **только SHA-256 от случайного 256-битного токена**, срок действия и время отзыва. Отозванный или истёкший сеанс не доступен.
- PgAccounts: пул до 5 подключений, ожидание подключения до 5 секунд; значения SQL передаются через параметры.
- Версионированная миграция: crates/adapters/migrations/202610120001_create_accounts.sql. Не менять уже применённую миграцию задним числом.
- Учётные записи и каталог используют один `MIGRATOR` из `bokarust-adapters`: следующая версия `202610120002_create_books.sql` создаёт книги. Это предотвращает расхождение историй SQLx.
- Нормализация почты находится в domain, Argon2id и случайные токены — в adapters. В асинхронных HTTP-обработчиках хеширование нужно запускать вне потока обработки, через spawn_blocking.

## Подготовка и миграция

Не записывать реальные пароли и DATABASE_URL в Git. PostgreSQL должен быть доступен по локальному интерфейсу или частной сети, у сайта — отдельный пользователь с минимально нужными правами.

В окружении задать DATABASE_URL (секрет вне истории команд), затем выполнить общую миграцию (название команды сохранено для совместимости):

    cargo run --package bokarust-adapters --bin migrate_accounts

Пример структуры адреса, не настоящий секрет: postgres://bookarust:***@127.0.0.1:5432/bokarust

Миграции применяются **до приёма запросов пользователей**, а не во время первой регистрации. Организовать отдельную резервную копию и проверить восстановление.

## Проверка

Обычные тесты Rust проверяют нормализацию почты, разные соли Argon2id, ошибочный пароль и генерацию токенов.

В GitHub Actions для отдельного теста запускается **одноразовая PostgreSQL 18**. Тест применяет миграцию, создаёт пользователя, проверяет запрет повторного email, поиск/отзыв/истечение сеанса. Тест не имеет доступа к рабочей БД; тестовые записи удаляются.

Локальная проверка при доступной одноразовой БД:

    export TEST_DATABASE_URL='postgres://postgres:...@127.0.0.1:5432/bokarust_ci'
    cargo test -p bokarust-adapters --test integration_postgres_accounts -- --ignored

В CI интеграционный тест вызывается при изменении пакета adapters и при полном проверочном запуске. Отсутствие адреса PostgreSQL во время запуска должно завершаться ошибкой, а не мнимым успешным тестом.
