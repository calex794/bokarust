# BKR-95 — первая HTTP-авторизация на Rust

Требование: [BKR-95 в Notion](https://app.notion.com/p/3f632a84beec81e495d8cc397cc3f058). Исходный booka не изменяется.

## Границы

- Используется существующий модульный Axum-сервер, PgAccounts, Argon2id и PostgreSQL 18.
- Формы не требуют JavaScript: GET/POST /register, GET/POST /login, GET /me и POST /logout.
- После регистрации/входа ответ 303 на строго заданный путь /me. Параметры next/return_to не поддерживаются (нет открытого перенаправления).
- Токен сеанса генерируется через OsRng, содержит 256 случайных бит; PostgreSQL хранит SHA-256. Сеанс действителен не более 7 суток, отзыв немедленно исключает доступ к /me.
- Регистрация создаёт пользователя и первый сеанс в одной SQL-транзакции; при сбое ничего не остаётся. Уникальность нормализованной почты обеспечивает БД.
- Argon2id выполняется в spawn_blocking, одновременно не более четырёх операций. Неизвестная почта тоже оплачивает одно вычисление Argon2id.
- Защита форм: случайный 256-битный CSRF-токен в скрытом поле и в cookie, сравнение постоянного времени, запрет повторяющихся cookie; SameSite=Strict. Секрет меняется при потере cookie и очищается при выходе.
- Cookie при HTTPS: __Host-bokarust_sid / __Host-bokarust_csrf; Secure, HttpOnly, SameSite=Strict, Path=/, без Domain. Ответы авторизации: Cache-Control no-store, CSP, запрет встраивания, nosniff.
- Для локального HTTP разрешена BOKARUST_INSECURE_COOKIES=1 только на loopback, с отдельными именами dev-cookie.
- Включён ограничитель 5 попыток входа в 15 минут на хеш нормализованной почты, размер памяти ограничен 10 000 ключами. Это локальное ограничение процесса, не распределённая защита.
- Параметры данных проходят нормализацию и ограничения (имя 1–80, пароль 12–128 Unicode-символов, форма не больше 8 КБ). Отображение имени и почты HTML-экранировано.

## Проверки

- Обычные unit-тесты: валидаторы, формат и свойства cookie, CSRF, дублирование, ограничение попыток.
- GitHub Actions: PostgreSQL 18, отдельная одноразовая БД bokarust_auth_test, cargo test -p bokarust-web --test auth_http_postgres -- --ignored.
- HTTP-контракт: отсутствие cookie/CSRF → 403, регистрация → 303 /me, гостю /me недоступен, HTML-инъекция имени экранируется, отзыв → старый сеанс недействителен, неверный пароль 401, повторный вход, 409 на дубль, запрет открытого перенаправления, GET /logout → 405. База для теста проверяется по точному имени перед любыми изменениями.

## Не готово к публичному развёртыванию

Нужны HTTPS и корректная настройка обратного прокси, распределённая защита от перебора/ботов (локальный limiter работает на одну реплику), подтверждение адресов почты и восстановление пароля, мониторинг/аудит, автоматическая очистка истёкших сеансов, проверка нагрузочного и безопасности. Не выдавать демо-режим за производственный сайт.
