# BKR-87 — первый путь автора

Требования: [BKR-87](https://app.notion.com/p/3f632a84beec81399957d8f0ea1acee9), [SaveChapter — BKR-98](https://app.notion.com/p/3f632a84beec8141b849f7c8d542c628).
Исходный booka остаётся неизменным.

## Пользовательский путь

1. Автор входит и переходит из /me в /me/books.
2. По /books/new создаёт книгу с уникальной парой (исходное произведение, язык).
3. Управляет книгой через /me/books/{id}; добавляет текст через /books/{id}/chapters/new.
4. **Одно нажатие «Сохранить» немедленно публикует новую неизменяемую версию.** Нет черновиков и отдельного PublishChapter.
5. Изменение главы по /books/{id}/chapters/{chapter_id}/edit обязано предъявить ожидаемую редакцию и новый ключ команды. Две вкладки с общей редакцией: один успех, один 409.
6. Бесплатная версия читается по /reader/{id}; платная не доступна по публичному маршруту, пока нет покупок.

## Данные и правила

- Книга получает одного владельца (books.owner_user_id). Ранее созданные книги с NULL владельцем нельзя редактировать через новый интерфейс. Права проверяются по действующей сессии и в запросе PostgreSQL для каждой записи, а не только по загруженной странице.
- Команда сохранения в одной PostgreSQL-транзакции меняет название, платность/цену, историческую версию и опубликованный указатель. При сбое — откат всего. Новый текст — максимум 50 000 символов. Версии не обновляются на месте. Если содержание не менялось, не создаётся лишняя версия.
- Отдельные таблицы book_create_commands и chapter_save_commands сохраняют результат ключа. Повтор того же ключа и нагрузки возвращает тот же ответ после фиксации. Тот же ключ с другой нагрузкой даёт 409. Уникальность гарантирует PostgreSQL и при одновременных запросах.
- chapter_first_release_events фиксирует **ровно один долговечный факт первого выпуска** внутри той же транзакции. Отправка уведомлений, получатели и повторная доставка будут подключены отдельным этапом.
- Cookie сеанса HttpOnly/SameSite, CSRF плюс Origin, запрет кеша для частных страниц. Открытие форм из нескольких вкладок сохраняет действующий CSRF-токен.
- Для оплаты нужен отдельный перенос купленной закреплённой версии и политика удаления. Старый ON DELETE CASCADE пока не считается совместимым с правом покупателя. Роли команд и отложенный выпуск не реализуются в этом первом пути.

## Приёмка

Реальный PostgreSQL HTTP-тест проверяет: гостя, вход/сеанс, создание книги, ограничение чужого автора, запрет чужих правок, создание главы и публичное чтение, блокировку скриптов, повторы с тем же и изменённым ключом, две вкладки/409, неизменяемый старый текст, предел 50 000, изменение цены и приватность платной главы, единичное событие первого выпуска и отзыв сеанса.

Команды: cargo fmt --all -- --check; cargo check --workspace --all-targets; cargo clippy --workspace --all-targets -- -D warnings; cargo nextest run --profile ci; TEST_DATABASE_URL=postgres://.../bokarust_ci cargo nextest run --profile ci --package bokarust-web --run-ignored only -E 'test(integration_author_)'. CI и ночная проверка запускают испытание отдельно. До успешного CI нельзя объявлять BKR-87 выполненной.
