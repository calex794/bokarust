# В4.01 · Закреплённые купленные версии — первый срез

Связанные правила: [В4.01](https://app.notion.com/p/3f632a84beec81b08409c15ba1f8bf15), [BR-057](https://app.notion.com/p/3f632a84beec81e29becf6f446a0037b), [BR-059](https://app.notion.com/p/3f632a84beec81388163d4f2f188895a), [BR-060](https://app.notion.com/p/3f632a84beec81ec9378ce8e899bc47f), P-05/P-06/P-10 продуктовой конституции.

## Что включено

- `chapter_purchase_facts` содержит неизменяемый факт подтверждённой оплаты: user_id, chapter_id, version_id, settlement_reference, сумму и валюту. Факты нельзя править или удалять; ключ внешнего подтверждения уникален.
- `library_purchased_chapters` отдельно связывает владельца, главу, исторический факт и `active_version_id`. Составной внешний ключ запрещает выдавать чужую редакцию или чужую покупку. В первом срезе автоматических обновлений/повышений версии нет.
- `chapter_purchase_revocations` хранит отдельно возврат/отмену. Отмена немедленно закрывает доступ, но не уничтожает историю.
- `GET /me/purchases`: только личный список приобретений. Записи со снятым доступом показывают соответствующий статус без ссылки.
- `GET /me/purchases/{chapter_id}`: **только закреплённая купленная версия**, полученная по связке user + purchase + library, с проверкой отзывов/блокировки в том же SQL. Никогда не берёт `chapter_publications.version_id`. Исходный HTML главы экранируется ограниченным Markdown; страница без скриптов, `no-store`, `noindex`, строгая CSP.
- При обычном скрытии (`visibility='draft'`) и неразрушающем удалении книги (`books.is_deleted=true`) старый купленный текст остаётся доступным. При `books.admin_hold` или `chapters.admin_hold` — недоступен. При `chapters.is_deleted` пока отказываем до отдельного решения о физическом удалении главы. Не считать техническое отображение текущих полей окончательно утверждённой матрицей продуктовых статусов.
- Внешние ключи блокируют физическое удаление книги/главы/версии, способное каскадно уничтожить историю покупки. Перед правовым физическим удалением нужен отдельный процесс урегулирования.
- `/me/library` и `reader_book_positions` остаются **только прогрессом бесплатного чтения** и не выдают доступ к купленной версии.

## Важно: покупки за деньги пока НЕ включены

В этом PR **нет публичной кнопки покупки, зачисления кошелька, списания, финансового журнала и проверки внешнего платежа**. Никто не может создать право через общедоступный HTTP-маршрут. Тестовые записи `chapter_purchase_facts`/библиотеки загружаются **только внутри тестовой PostgreSQL**, чтобы проверить уже приобретённые права, а не имитировать реальную оплату.

Следующая отдельная операция — **доверенное подтверждение оплаты и выдача права в одной PostgreSQL-транзакции**, с запретом повторного списания/покупки, откатом при сбое и журналом. Только после неё допустим пользовательский путь «Купить». Сохранённый прогресс, cookie, HTML и фоновый JS никогда не считаются доказательством оплаты.

## Обязательная приёмка

- Гость и чужой пользователь не читают закреплённый текст и не видят записи другого пользователя; публичный путь не раскрывает платную главу.
- Текст остаётся той же редакцией после публикации новой, скрытия и обычного удаления книги.
- Блокировка книги/главы и запись об отмене закрывают чтение, сохраняя историческую запись и понятный статус владельцу.
- Повтор финансовой ссылки отвергается уникальностью, подмена версии внешним ключом, изменение исторического purchase триггером; физическое удаление не уничтожает проданные версии.
- Сквозные HTTP + настоящая PostgreSQL, Rust тесты, проверки архитектуры; нет изменения правил обычной читалки.

Отдельные продуктовые вопросы: точное сопоставление «hard block» с полями Book, удаление отдельной главы, спорная прямая покупка скрытой книги, роли модераторов, финансовые возвраты и дальнейшее `explicit upgrade` версии.
