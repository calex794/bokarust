## Реализованный минимальный публичный сценарий

Главная и каталог отображают ссылки /books/{id}; карточка книги показывает первые 200 опубликованных бесплатных глав с /reader/{chapter_id}. Страница читателя отдаёт выбранную опубликованную версию. Исходный Markdown временно показывается с HTML-экранированием; это предотвращает XSS, но ещё не полноценный Markdown-рендеринг.

Прямой URL читателя **не обходит проверку в SQL**: книга public без admin_hold / is_deleted; глава public + free без admin_hold / is_deleted, release_at наступил; существует связанная опубликованная версия. Нет раскрытия черновых версий, платных текстов и чужих книг. Ошибка базы → HTTP 503, скрытый объект или недопустимый ID → 404.

В отличие от Booka, защищённые платные и закреплённые в библиотеке версии пока не поддерживаются. Не используем факт входа как достаточное разрешение; доступ к платным текстам по публичному маршруту остаётся закрытым.

## PostgreSQL и инварианты

Новая миграция 202610120004_public_reading.sql. Старые миграции не переписаны. Добавлены флаги book.admin_hold / book.is_deleted; таблицы chapters, chapter_versions и chapter_publications. Композитный FK (chapter_id,version_id) у publication не позволяет указать версию чужой главы; версии сохраняются отдельно и не перезаписываются при смене указателя.

## Проверки

Rust workspace запускает проверку форматирования, сборки, Clippy, unit tests, затем отдельно обязательные интеграционные тесты PostgreSQL-каталога и reader. Ночной полный аудит тоже включает reading contract. Тест без TEST_DATABASE_URL падает при явном запуске, база строго bokarust_ci или bokarust_test.

Проверяются: публичные ссылки каталога и книги, экранирование HTML, невидимость неопубликованной версии, смена published pointer, запрет доступа к draft/paid/held/deleted/future/unpublished/hidden-book главам через прямой URL, внешний ключ чужой версии, удержание всей книги и 503 после закрытия БД.

Тест добавляет отдельные книги со случайными исходными идентификаторами и удаляет только собственные записи. Предыдущий контракт каталога использует TRUNCATE только в изолированной БД и обновлён с учётом зависимых таблиц.

## Следующий этап

Операции создания и публикации глав через веб, история версий и права доступа купивших; безопасное преобразование Markdown; пагинация книг с более чем 200 главами; S3 при необходимости. Независимый аудит безопасности и эксплуатационная готовность не подтверждены.
